Ruby on Rails คืออะไร?

แนวคิดหลัก, MVC Pattern, Convention over Configuration

💎 Rails คืออะไร?

Ruby on Rails (Rails) คือ Web Application Framework เขียนด้วยภาษา Ruby เน้นความเร็วในการพัฒนา มีหลักการสำคัญ 2 ข้อ:

📐 Convention over Configuration (CoC)
Rails กำหนดมาตรฐานให้แล้ว — ไม่ต้องตั้งค่าอะไรมาก แค่ทำตาม convention ก็ทำงานได้เลย
🔁 Don't Repeat Yourself (DRY)
เขียนโค้ดครั้งเดียว นำมาใช้ซ้ำได้หลายที่ — Rails มี helper, partial, concern ช่วยให้โค้ดไม่ซ้ำซ้อน

⚡ Rails ทำอะไรได้บ้าง?

  • 🌐 Web Application — สร้างเว็บครบทั้ง Frontend + Backend
  • 🗄️ Database ORM — Active Record จัดการ DB โดยไม่ต้องเขียน SQL
  • 📋 REST API — สร้าง JSON API ได้ด้วย API-only mode
  • 📧 Email — Action Mailer ส่ง email ได้ในตัว
  • ⚡ Real-time — Action Cable สำหรับ WebSocket
  • 🔐 Auth — Devise gem ทำ Authentication ได้ง่าย

🏛️ Class — สิ่งที่ Rails ใช้เยอะมาก

class Animal
  attr_accessor :name, :age    # สร้าง getter/setter อัตโนมัติ

  def initialize(name, age)
    @name = name    # Instance variable
    @age  = age
  end

  def speak
    "#{@name} พูดอะไรบางอย่าง"
  end
end

class Dog < Animal    # Inheritance
  def speak
    "#{@name} พูดว่า: โฮ่ง!"
  end
end

dog = Dog.new("บุญมี", 3)
dog.speak    # "บุญมี พูดว่า: โฮ่ง!"
dog.name     # "บุญมี"
dog.age = 4 # setter จาก attr_accessor

📋 CRUD Controller สมบูรณ์

# app/controllers/articles_controller.rb
class ArticlesController < ApplicationController
    before_action :set_article, only: [:show, :edit, :update, :destroy]

  # GET /articles
  def index
    @articles = Article.all.order(created_at: :desc)
  end

  # GET /articles/:id
  def show
  end

  # GET /articles/new
  def new
    @article = Article.new
  end

  # POST /articles
  def create
    @article = Article.new(article_params)
    if @article.save
      redirect_to @article, notice: "สร้างบทความสำเร็จ!"
    else
      render :new, status: :unprocessable_entity
    end
  end

  # GET /articles/:id/edit
  def edit
  end

  # PATCH /articles/:id
  def update
    if @article.update(article_params)
      redirect_to @article, notice: "แก้ไขสำเร็จ!"
    else
      render :edit, status: :unprocessable_entity
    end
  end

  # DELETE /articles/:id
  def destroy
    @article.destroy
    redirect_to articles_path, notice: "ลบบทความแล้ว"
  end

  private

    def set_article
    @article = Article.find(params[:id])
  end

    def article_params   # Strong Parameters — กันช่องโหว่
    params.require(:article).permit(:title, :body)
  end
end

📤 render vs redirect_to

Methodทำอะไรใช้เมื่อ
render :newแสดง view โดยไม่เปลี่ยน URLForm มี error
redirect_to @articleส่ง HTTP 302 → browser ไปหน้าใหม่บันทึก/ลบสำเร็จ

🔒 Strong Parameters

# ป้องกัน Mass Assignment Attack
# ถ้าไม่มี Strong Params user อาจส่ง
# { admin: true } มาได้!

def article_params
  params
    .require(:article)
    .permit(:title, :body, :published)
end

✅ Validations — ตรวจสอบข้อมูลก่อนบันทึก

class Article < ApplicationRecord
  # ต้องมีค่า
  validates :title, presence: true
  validates :body,  presence: true

  # ความยาว
  validates :title, length: { minimum: 5, maximum: 100 }

  # ห้ามซ้ำ
  validates :title, uniqueness: true

  # รูปแบบ (regex)
  validates :email, format: { with: URI::MailTo::EMAIL_REGEXP }

  # ตัวเลข
  validates :views, numericality: { greater_than_or_equal_to: 0 }

  # รวมหลาย validation
  validates :title,
    presence: true,
    length: { minimum: 5, maximum: 100 },
    uniqueness: { case_sensitive: false }
end

# ตรวจสอบ validation ใน console
article = Article.new
article.valid?        # false
article.errors.full_messages
# ["Title can't be blank", "Body can't be blank"]

class ArticlesController < ApplicationController
  before_action :authenticate_user!, except: [:index, :show]
  before_action :set_article,        only:   [:show, :edit, :update, :destroy]
  before_action :authorize_user!,     only:   [:edit, :update, :destroy]

  def index
    @articles = Article.published.recent.page(params[:page]).per(10)
  end

  def show
    @comment = Comment.new
  end

  def new
    @article = Article.new
  end

  def create
    @article = current_user.articles.new(article_params)
    if @article.save
      redirect_to @article, notice: "✅ สร้างบทความสำเร็จ!"
    else
      render :new, status: :unprocessable_entity
    end
  end

  def edit; end

  def update
    if @article.update(article_params)
      redirect_to @article, notice: "✅ แก้ไขสำเร็จ!"
    else
      render :edit, status: :unprocessable_entity
    end
  end

  def destroy
    @article.destroy
    redirect_to articles_path, notice: "🗑️ ลบบทความแล้ว"
  end

  private

  def set_article
    @article = Article.find(params[:id])
  end

  def article_params
    params.require(:article).permit(:title, :body, :published)
  end

  def authorize_user!
    redirect_to root_path, alert: "ไม่มีสิทธิ์!" unless @article.user == current_user
  end
end

# app/controllers/comments_controller.rb
class CommentsController < ApplicationController
  before_action :authenticate_user!

  def create
    @article = Article.find(params[:article_id])
    @comment = @article.comments.new(comment_params)
    @comment.user = current_user
    if @comment.save
      redirect_to @article, notice: "💬 เพิ่มความคิดเห็นแล้ว"
    else
      redirect_to @article, alert: @comment.errors.full_messages.to_sentence
    end
  end

  def destroy
    @comment = Comment.find(params[:id])
    @comment.destroy if @comment.user == current_user
    redirect_to @comment.article, notice: "ลบความคิดเห็นแล้ว"
  end

  private
  def comment_params
    params.require(:comment).permit(:body)
  end
end

⚡ แก้ N+1 Query ด้วย includes

❌ N+1 Problem
# Controller
@articles = Article.all

# View
@articles.each do |a|
  a.user.email  # Query ใหม่ทุก row!
end
# 1 + N queries
✅ Eager Loading
# Controller
@articles = Article
  .includes(:user, :comments)
  .all

# View
@articles.each do |a|
  a.user.email  # ไม่ query เพิ่ม
end
# แค่ 2-3 queries

✅ Best Practices สรุป

  • Fat Model, Skinny Controller — Logic ใน Model ไม่ใช่ Controller
  • Strong Parameters — ใช้ทุกครั้งที่รับ params
  • includes() — แก้ N+1 query เสมอ
  • before_action — หลีกเลี่ยงโค้ดซ้ำใน actions
  • Scope — Named queries ที่นำมาใช้ซ้ำ
  • Partial — แบ่ง View ให้เล็กลง
  • เขียน Tests ด้วย RSpec
  • ใช้ database index บน columns ที่ query บ่อย
